# 可信样本数据基座（v0.9.4）

## 数据语义

`training_samples` 是不可覆盖的用户反馈事件，**不是标准答案**。安装 ID 为客户端自报，任何人可以伪造提交；加盐标识与配额只能限制滥用，不能证明是真人、独立账号或可靠判断。引擎来源和命中规则仅为观察事实，不能作为训练标签。

- `manual-spam`：用户显式标记垃圾并拉黑成功。仍可能误判。
- `accepted-detection`：用户单条采纳检测并拉黑成功，有提示偏差。
- `batch-block`：页面批量采纳检测，不能视为逐条独立审阅。
- `false-positive`：页面徽章或侧栏点击误标，加入个人白名单。
- 普通白名单添加、关注保护、个人用途拉黑、社区清理、未处理的检测不创建样本。

独立事件不写 reports / rescues / active_labels，不改变计票。既有社区同步继续按原有规则运行。仅从 v0.9.4 的明确操作开始采集；不把历史黑白名单补造为可信内容样本。

## 当时的证据

共享 schema v1 保存公开正文（4000 字符）、昵称（160）、简介（1000）、截断字段、对方 handle/可用 X ID、帖子 ID、采集/操作时间、扩展版本、词库版本、检测来源/规则/信号。自定义关键词 ID 脱敏，不传用户输入短语或理由。正文不做归一化；规范化和家族键用于离线派生，不覆盖原始证据。

`observedAt` 是当前页面扫描时间；排队动作沿用扫描证据而非事后抓取。缺失简介、图片、引用上下文不能假装已收集；本版没有截图、图片理解、完整会话上下文、全部规则执行轨迹或模型输出。后续可通过 schema 升级增补，不能推断旧字段。

样本和本地动作记录同一次 storage 写入。每事件一个 storage key，避免多个页面同时追加数组覆盖。用户关闭「名单上传」后不采集、不发送；关闭前的积压仍保存在本地，重开后可以补交。后台在收到消息、启动/升级、社区同步时补交，15 秒网络超时，失败保留，按已确认 ID 删除。无无限同步重试。服务端逐条拒收非法样本，不连带拒绝同批有效记录；拒收证据转入本地 `trainingSampleRejected:*` 保留错误，避免堵住补交队列。storage 满时动作本地记账仍可能失败，错误不可解释为网络已提交。

## 后端及复核

- POST `/v1/training-samples`：每批 20，450 KB 上限；安装每日 300 次样本预算，IP 每日 1000，含重试。服务端收到时间独立于客户端时钟，拒绝明显未来时间。
- `(installation_id, event_id)` 唯一；重试不覆盖首次收到的证据，改判必须新事件 ID。
- 后台 `/api/admin/samples` 与 `/:id/review` 继承管理域名、Access、CSRF、no-store 边界；不通过公开名单或快照暴露原文、身份标识。
- `training_sample_reviews` 追加审阅历史，记录审阅人、时间、垃圾/正常/不确定、家族 ID、语义标签和必填理由。最新复核为有效结论；改为不确定撤销该记录的评测资格。
- 语义标签为人工标注：招揽、联系方式导流、引用、否定、上下文不足。它们是以后训练和分析的监督数据，本版本未部署语义模型。
- 后台用户反馈页查看证据、保存复核、游标导出。导出固定样本和复核的最大 ID，防止分页期间新增记录导致无限导出或审阅版本混杂。

不要仅看检测来源就选“垃圾”。同时审阅正文、昵称和简介，区分账号偏好与内容标签；语境不足选“不确定”。模板家族必须人工统一：同一招揽目标的轻微改写和近似模板不应任意分成多个 ID。多个安装反馈不等于多个独立人类判断。本版一位维护者审定可入候选评测集；高风险家族、争议样本和正式发布集仍应独立二次复核。

## 时间和家族评测

```sh
node scripts/build-sample-dataset.mjs samples-export.json dataset.json 2026-10-01T00:00:00Z 2026-10-08T00:00:00Z
# predictions.json: [{"id":123,"label":"spam"},{"id":124,"label":"normal"}]
node scripts/build-sample-dataset.mjs samples-export.json dataset.json 2026-10-01T00:00:00Z 2026-10-08T00:00:00Z predictions.json
```

以上日期只是调用示例，不是当前数据评测结果。

1. 只选有明确人工复核、家族、正文且未截断的正反例；不确定、未审、缺失材料、冲突标签排除。
2. 按人工家族、同账号/X ID、同帖、精确内容哈希、去数字/emoji/分隔符的近似模板键，构建连通组。
3. 使用客户端观察时间与服务端收到时间中的较早值，保守限制新样本进入未来测试集；客户端时钟不能证明真实发布时间。
4. 跨时间边界的整组隔离，不把组中旧条目放训练、新条目放测试。保留下来的组只进入训练、验证、测试其中之一。每组精确内容去重。
5. 导出包含证据与复核版本、划分边界和 SHA256。预测必须逐测试样本完整提供；输出 TP/TN/FP/FN、精确率、召回率、正常误标率及逐家族指标。无正例或无反例标为数据不足，分母为零的指标为 null。

模型输入应白名单选取公开正文、昵称、简介；不得把用户动作、复核结论、规则 ID、检测来源或文件分区当作输入特征，否则会形成标签泄漏。数据集保留审计元数据是为了复现，不代表可把整个 JSON 直接喂给模型。

粗模板键不是语义聚类。大幅改写仍依赖人工家族整理；图片-only、缺失上下文的内容不进入此文本评测集。待审事件也参与关联隔离，避免忽略旧家族存在的事实。

这些数据来自用户处理行为，存在选择偏差：正常且未被标记的内容、用户没注意到的漏检不会自然进入样本池。因此本版指标仅说明**人工复核反馈集合**的表现，不能代表整个 X 评论流的真实误标率/召回率。后续需要经明确授权采集独立抽样的正常背景与新家族漏检集，并固定发布评测集及精度门槛。当前不凭空设定通过阈值、不声称已有新家族准确率，也不自动训练或发布模型。

## 运维与删除

先应用 `0026_training_samples.sql`，再部署 Worker 与 admin；旧扩展不依赖新表。回滚 Worker 不删除表，保留证据与审计。

安装删除请求核验后，在同一 D1 batch/事务内先删除该安装样本关联的 `training_sample_reviews`，再删除 `training_samples`，并处理原有 reports/rescues/active_labels 删除流程。样本 hash 不公开；不得把原始安装 UUID 写到 SQL、访问日志或工单。限流计数 cron 清理 7 天以前的行，证据不会随计数过期删除。导出文件也需按删除请求重新生成；公开仓库不提交真实样本。
