# 从单条短语到多证据判断

## 已核实的缺口

用户提供的 HollyOlexaapsz、LisandraNa3bd、AldoDanielski、LeahTappenuf6、CletaDarusij 五个公开评论样本，正文使用歌词/口语、emoji 与随机数字；主要招揽信息放在昵称中。第一条已在真实 X 帖子上核对昵称与正文并确认未标注；生产管线重跑也不命中。与此前空订阅问题不同，这次是已启用规则的覆盖缺口。

Holly 和 Lisandra 的正文去除 emoji、数字和分隔符后，与 Cleta 的正文相同。前两个昵称含明确招揽组合，Cleta 的昵称单独不足以确定垃圾性质，正文则另有长数字载荷。

## 0.9.3 已实现

1. 昵称中的成对证据：寻找单男/单女 + 看简介/主页/置顶；原文 🈷 符号 + 真实/线下约见；原文 🈷 + 邻接招揽用法 + 资料导流。拒绝、反诈提示等反例不算邀请。仅消费昵称，不把引用正文或简介里的讨论误当成昵称邀请。
2. 本地模板关联：至少两个不同账号符合直接昵称规则，且另一账号复用相同正文骨架并携带 ≥11 位数字载荷时，给出待确认标注。候选可先于证据账号出现，证据齐备后只使相关账号的扫描缓存失效。
3. 不递归学习：关联命中、一般关键词命中不能成为新的直接证据来源。个人白名单、关注保护、自己和社区保护名单不参与证据来源。
4. 本地时效与容量：15 分钟、最多 512 个正文模板，每个模板最多 64 个账号；不写入持久存储，不上传该索引。结果属于 keyword 确认层，不自动拉黑、不自动加社区票。
5. 撤销：来源账号受保护或其直接证据消失后，当前页面的关联结果会重新判定并撤回；开关及规则变化时清空关联索引。
6. 验收覆盖：五个正例、正常歌词/动漫昵称/学生昵称、普通月份、拒绝表达、报价/订单号等反例；同账号重复不增加证据数、推断不扩散、时效和容量、观察顺序、白名单撤销。真实 Chromium 在冷启动、变体表降级恢复、已有远端缓存三种状态中运行整套页面回放。

## 尚未实现及实际限制

- 此层不是语义模型，也不是自动训练系统。名字和正文大幅改写、纯图片引流、全新网络且未出现直接证据时，仍可能漏检。
- 单独打开 Cleta 的帖子而未在本页观察到足够证据来源时，不应仅凭“兔女郎”昵称把它判成垃圾。本轮回放证明的是五个样本共同出现时的识别与撤销机制，不是统计意义的整体准确率。
- 直接昵称规则本身仍是启发式。两名账号具有直接证据不等于两名独立用户已确认它们；它只能支持本地人工复核，不能升级为社区事实。
- 存心复制正常用户正文的攻击者可能污染模板关联；多证据、候选附加信号、保护名单与禁止递归降低影响，但不能保证消除攻击。不要把它升级成自动账号处罚。

## 长期路线

长期收益来自数据和评测闭环：手动确认的正例与白名单反例保留同次证据；按时间及模板家族切分训练与测试，避免同模板泄漏；对来源独立性、恶意投票和概念漂移做治理；新增规则或语义分类器先影子评测，再小范围启用，并可撤回。

分类应区分直接高置信证据、待确认关联和证据不足。可进一步引入本地或服务端语义模型，分别理解招揽意图、引用/否定、图片文字和资料导流，再与可信行为数据组合；模型不能直接决定账号处罚或把自己的推断当训练真值。没有必要为了抗对抗把整个开源引擎转成闭源。

同一段可见内容可以来自正常用户或垃圾账号，单靠客户端看到的一条短文本无法保证同时零漏报和零误报。应报告可复现的分家族效果及误报率，而不是以“全部测试通过”代替真实识别质量。
