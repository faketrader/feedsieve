# X 过滤项目对照研究（2026-09-13）

研究对象：

- [ZPVIP/x-spam-filter](https://github.com/ZPVIP/x-spam-filter)，审阅提交 `399158e50e78cd853c10723fd23f02acca4ee5cd`，Apache-2.0。
- [amahteru/x-comment-blocker](https://github.com/amahteru/x-comment-blocker)，审阅提交 `b1a65653e8302d32c1b3297b926865eb4e3a68f6`，MIT。

本次只吸收设计经验并独立实现，没有复制两个项目的源码或词库。原因不是许可证禁止使用，而是 FeedSieve 的规则需要保留稳定 ID、分类、命中字段、远程签名、误标反馈和人工操作边界；整段移植会破坏这些契约，也会把外部项目的误报面一起带进来。

## 结论

两个项目都证明了三个方向值得保留：DOM 增量处理、输入 revision 缓存、关键词批量匹配。FeedSieve 已经具有前两项，而且页面控制器还增加了脏节点倒排索引、8ms 分片、插件自身 DOM 反馈环过滤和虚拟列表节点复用处理。本次补齐第三项：普通字面规则被编译为 Aho-Corasick 多模式自动机，同一昵称、账号、正文和简介只扫描一次；ASCII 整词与有序词组继续使用各自的严格语义。

这一实现保留规则原顺序、规则 ID、首个命中字段和可读理由。自动机输出全部重叠候选，因此不会采用 `x-comment-blocker` 中“短词存在就删除包含它的长词”的裁剪方式。后者节省规则数，但会丢掉更具体、通常也更适合误标审计的长短语。

## 值得吸收的经验

| 项目 | 机制 | FeedSieve 处理 |
|---|---|---|
| x-spam-filter | MutationObserver 只处理新增/变化节点；WeakMap 保存文章签名 | 已有，保留现有更完整的 `PageScanController` |
| x-spam-filter | 普通关键词分片合并，避免逐词正则 | 独立实现多模式自动机，支持重叠命中和稳定规则 ID |
| x-spam-filter | `requestAnimationFrame` 加定时器兜底 | 当前固定 300ms 调度加 8ms 分片在后台标签页也能工作；不引入双调度器 |
| x-spam-filter | 远程词库失败时保留本地版本 | 已有签名 manifest、SHA-256、schema 校验和 last-known-good，强于裸远程文本同步 |
| x-comment-blocker | 快速输入签名，DOM 未变化就跳过 | 已有 article revision；本次再让同轮启发式共享输入对象以复用批量结果 |
| x-comment-blocker | 保存命中正文、昵称和帖子 ID 供复盘 | 本轮已将 `post_id`、正文、昵称、简介、`rule_id`、`signal_ids` 接入报告证据链 |
| x-comment-blocker | 持久拉黑队列、429 暂停、重试上限 | FeedSieve 已有 24h 配额、429 风暴降级、认证失效门控、暂停/恢复和 kill switch |

## 没有吸收的做法

- 不按“包含 emoji”“包含特殊字符”“出现 Grok”单独判垃圾。这些信号在正常用户中太常见，只能作为有强锚点时的弱证据。
- 不把关键词命中直接变成自动拉黑。FeedSieve 的黄框会进入用户操作清单，误标成本高，最终动作继续由用户决定。
- 不整包导入外部词库。`x-comment-blocker` 的同一文件混有成人引流、仇恨词、VPN/币圈营销、具体用户名及 `同城`、`附近的`、`无偿` 等宽词；类别边界和误报预算与 FeedSieve 不一致。
- 不把规则表和阈值保密当作防线。开源客户端始终可被观察；长期防线是独立保留集、分组回放、签名发布、结构化证据和快速撤回。
- 不直接采用外部自动拉黑 API 调用。FeedSieve 继续复用自己的 X 能力探测、账号 ID 解析和响应式预算。

## 词库比较的限制

静态精确字符串比较中，`x-spam-filter` 的 184 个普通唯一词有 12 个与 FeedSieve 当前词条完全相同；`x-comment-blocker` 排除注释与正则后有 785 个普通唯一词，只有 4 个完全相同。这个数字不能解释为覆盖率：FeedSieve 有有序词组、Unicode/繁简/部首/同形字符归一化、拼音家族和宽松标点匹配，同一话术可能无需同字词条就能命中；反过来，存在同一个短词也不证明上下文判断可靠。

外部列表可作为候选发现源，不能直接作为真值。后续新增规则必须先记录来源与目标家族，再通过正常语境、否定/引用、成人但非垃圾内容和未知模板时间切分回放。只有在固定误标预算内带来增益的规则才进入签名词包。

## 本次落地

1. detector 在同一轮启发式判断中复用同一个标准化输入对象。
2. 关键词组一次计算全部规则的首个命中字段，普通非 ASCII 字面规则由 Aho-Corasick 自动机扫描。
3. ASCII 规则继续整词匹配，避免 `adult` 误中 `adulthood`；有序词组继续执行顺序与最大间距约束。
4. 纯标点或纯符号自定义词在归一化后为空，现被拒绝，避免空字符串匹配所有内容。
5. 回归用例覆盖重叠长短词、英文边界、有序词组、Unicode 规避、昵称/账号/正文/简介字段优先级和无意义自定义词。

这一轮解决的是确定性的重复扫描成本和一个误标边角，不等于完成“根治”。长期收益仍取决于检测报告中提出的结构化证据、投放家族关系、独立评测集和影子挑战者流程。
