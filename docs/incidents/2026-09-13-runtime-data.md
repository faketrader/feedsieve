# MV3 随包检测数据加载回归与修复

## 故障边界

0.8.4/0.9.0 把大 JSON 移出 JS bundle 后，内容脚本直接 fetch 扩展资源，引入对 `web_accessible_resources` 的依赖。变体表的 await 还阻塞了官方词库加载。Node 测试同步读取仓库文件，未覆盖这一浏览器运行时分支。

WAR 可以修复资源访问声明，但无法解决失败 Promise 永久缓存、初始化顺序及加载恢复后的扫描缓存问题。0.9.1 消除内容脚本对随包资源 fetch 的依赖。

## 当前架构

- 后台在每次 SW 启动时同步注册固定资源消息处理器，只接受本扩展的请求，以及三个明确允许的资源路径。
- 内容脚本与 popup 先读 `bundledData:<path>`。版本与当前扩展不符时，通过消息唤醒后台。后台从自己的扩展源读取文件，并按资源分别写入版本缓存。
- 同一 SW 内并发读取合并；每个资源独立成功或失败。fetch 超时 10 秒，消息等待上限 15 秒。失败不会永久污染 Promise 缓存。
- 缓存读写异常保留错误日志；缓存写入失败仍返回已经读取的数据。
- 随包缓存不写入 `keywordPacksSnapshotV2` / `communitySnapshotV2`，不改变远端验签、最后同步时间或节流语义。
- 变体表与词库独立加载。失败后在 5/10/15 秒触发有限重试，回到页面前台也会重试。恢复后清除归一化结果缓存、重建匹配规则，并使推文扫描缓存失效。
- 随包名单装载完成主动触发重扫。检测仍保留用户显式控制的拉黑边界。

## 验证与发版门槛

`src/lib/platform/runtime-data.test.ts` 覆盖浏览器消息分支、冷启动、后台并发读取、版本隔离、来源及路径限制、失败后恢复、归一化缓存恢复和 storage 配额失败。

`node scripts/smoke-extension-runtime.mjs` 加载真实生产 MV3 产物，使用隔离 Chromium 配置，不使用日常 Chrome 登录态。测试页面在 `https://x.com/home` 上由脱机 HTML 夹具提供，浏览器从进程启动就通过不可用代理阻断外网：

1. 无远端缓存冷启动：三类随包数据装载，`全国空降` / `全國空降` 得到标注，普通散步文本不标注；刷新后的热启动也正常。
2. 变体表文件缺失：普通规则继续标注，繁体样本暂不标注；恢复文件后无需刷新页面，繁体样本得到标注。
3. 两个场景都断言随包数据没有冒充远端同步快照。

该测试进入 GitHub Actions 和 `scripts/pack-store.sh`。本机首次运行前执行 `pnpm exec playwright install chromium`；Linux CI 使用 `--with-deps`。

打包脚本还直接从最终 ZIP 解析三类 JSON，检查结构与非空数据，并拒绝通过 WAR 暴露 community 数据。

这些结果证明扩展加载、降级和恢复链路。它们不替代真实登录 X 页面上的持续兼容性检查，也不代表所有垃圾话术都能被识别。

## 0.9.2：真实升级状态暴露的第二个初始化缺陷

0.9.1 的脱机冷启动验收通过，并不代表真实升级状态已覆盖。随后在用户正在使用的 X 标签页中确认：扩展是 0.9.1，已缓存远端词包 2026.09.13.2（735 条成人引流规则和 25 条 crypto 规则），包含 adult-fu-not-black，但 keywordRulesV1 不存在，随包词库目录未装载。

normalizeSettings 从 BUNDLED_KEYWORD_PACK_CATALOG 过滤默认订阅。已有远端快照时根本不必装载随包词库，所以这个模块变量可以始终为空，进而得到空订阅、零条启用的官方规则。单测的 Node 同步装载与无缓存浏览器夹具都掩盖了这一状态。

0.9.2 将默认订阅固定为产品配置，与目录加载解耦；明确关闭全部的 v3/v4 设置继续保持关闭。新增四项浏览器运行时回归，以及“已有远端缓存、无显式设置”的真实 Chromium 场景。浏览器夹具同时包含用户截图中的完整话术。在修复前，新场景稳定超时；修复后必须通过才能打包。

现场恢复：确认用户没有显式设置后，仅补入产品默认订阅，未操作拉黑。用户原页面立即出现 11 条黄框，包含截图中的 SenaBeenelsh、KylaBartlesy2w 等评论。此现场恢复与后续 0.9.2 代码修复是两个不同动作。
